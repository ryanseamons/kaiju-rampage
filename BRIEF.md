# Brief: Kaiju Rampage, a playable prototype

## Goal

A playable browser vertical slice of a survivor-like. You start as a tiny kaiju and grow into a city-flattening monster, destroying buildings and fighting the military. **The twist:** between waves, the city reacts to *your* run with an AI-written "breaking news" bulletin.

## Inspiration (claims are the posters', unverified)

- **The game:** @DannyLimanseta, https://x.com/DannyLimanseta/status/2102404362471428576. A retro Japanese-style survivor-like, vibe-coded in "just over 2 weeks": grow from a tiny kaiju into a massive monster, fight military robots, "4 kaiju, 3 biomes, hundreds of upgrades". Don't copy its assets or exact design. Use it as a genre reference only.
- **Build pipeline:** @chongdashu, Pressure Wash Panic, https://x.com/chongdashu/status/2103497553191051321. Opus 5.5 → image-gen in-game mockups first → 3D via Tripo/Blender → grey-box level → polish → first-time user experience. The video chapters cover cost and Wasm/WebGPU.
- **Long read on finishing a whole game with AI:** @builtbysketch, https://x.com/builtbysketch/status/2098777028078211283

## Vertical slice scope

- **Content:** 1 kaiju, 1 biome (a coastal city at night), one ~10-minute run.
- **Growth:** 3 size tiers. Each tier zooms the camera out, changes what you can crush (cars → houses → towers), and changes which enemies take you seriously.
- **Enemies:** 3 types (infantry, tanks, jets or a mech boss at the end of the run).
- **Upgrades:** about 15, offered 3 at a time on level-up (classic survivor-like).
- **The narration layer:**
  - At each wave end, a "BREAKING NEWS" card: a short anchor line plus a ticker that reacts to run stats (buildings destroyed, district, near-death moments, current size tier, upgrades taken).
  - Generated by Claude through a tiny local server that reads `ANTHROPIC_API_KEY` from the environment. The key never goes into the client bundle.
  - Default model `claude-haiku-4-5-20251001` for speed.
  - Fetch the bulletin while the wave is still playing, so the break never waits on it.
  - With no key or a failed request, use a pool of canned lines filled in from stats, so the game always works offline.
- **Feel:** screen shake, hit-stop, particles and chunky destruction. Juice matters more than content volume.

## Defaults (change them only with a logged reason)

- TypeScript + Vite.
- Rendering: 2D top-down pixel art (Phaser 3 or plain Canvas) **or** low-poly three.js. Pick one in the plan checkpoint and log why. This standalone repo can add dependencies freely.
- Assets: generated (image tools) or CC0 only. Write down where each came from in `ASSETS.md`.
- Controls: WASD/arrows to move, auto-attack plus one active stomp ability. It should also work with a gamepad if cheap.

## Done criteria (make these checkable)

1. `npm run build` passes, and `npm run dev` serves the game locally.
2. A Playwright script plays automatically (scripted input), survives into wave 3, and saves screenshots of: each size tier, a level-up choice, and a news bulletin card, with and without an API key.
3. The game runs smoothly on a laptop. Record the observed frame rate in the handoff.
4. The README covers how to run it, controls, where the narration key goes, and known gaps.
5. A short `NOTES.md` covers what took the most time, the rough AI cost, and what a full game would need next.

## Constraints

- Local only: no deploy, publish or push without asking.
- No copyrighted assets and no real people.
- Keep the narration prompt and the stats-to-prompt mapping in one file so it's easy to tune.
